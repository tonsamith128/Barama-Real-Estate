# Barama Auto Updater — Integration Status and Release Boundary (2026-10-20)

**Current installed staging baseline:** `0.9.22-dev`, five-step installer accepted; database metadata/version matched and 61 InnoDB base tables were read-only inspected. No current-install backup or SQL restore was performed.

**PR #108:** development; no staging/production deployment and no authorization to merge or activate unattended installation.

## Customer-facing functionality implemented or integrated

1. Installed license recognition and explicit publisher entitlement check, protected by admin authentication/CSRF; publisher signature must verify using a separately pinned Ed25519 key.
2. Existing root-private authenticated release transport and signed V2 ZIP verifier, with bounded archive/file safety checks.
3. Signed release inspection available through an authenticated POST; session result is anchored to archive SHA-256, trusted public-key catalog SHA-256, current installed version, release metadata and a ten-minute expiry.
4. **Preview signed changes**: administrator+CSRF POST re-verifies the real signed ZIP and derives the existing read-only file plan. Shows counts and up to 40 safe paths; session display expires and rejects spoofed versions/counts/paths and changed archive bytes.
5. Existing guarded `/updater/`: manual replacement-package compatibility and native migration flow, with admin password and backup confirmation. It is NOT unattended update installation.
6. Six-stage dashboard readiness table reports installation disabled, lack of recovery evidence and lack of independently authorized privileged worker.

## Existing source infrastructure that is NOT a complete installer

- `PublisherPrivateDeliveryV1`: owner-triggered root-private *download*, never install.
- `SignedReleaseInspector`, `VerifiedReleaseFilePlanV2`: cryptographic ZIP inspection and read-only per-file plan.
- `VerifiedUpdateBackupV2`: CLI private **file-only** backup (not database).
- `PrivateDatabaseBackupV2`: staging-only private SQL export receipt (not independently restored).
- `IsolatedUpdateTransactionV1` and `IsolatedMysqlRecoveryV1`: disposable rehearsals; reject real live website/database use.
- `OneClickOfflinePreparationV1` and `OneClickRecoveryJournalV1`: read-only/preparatory evidence and state-machine contracts, not a root installer.
- Draft PR #107: review-only staging inbox and handoff designed for *previous* v0.9.23 staging state. DO NOT cherry-pick or execute as an installer; revalidate against fresh 0.9.22-dev and browser-to-root security boundary before reuse.

## Nonnegotiable remaining requirements for `Install update`

- New, owner-signed and publisher-entitled **newer** test ZIP (signed with offline publisher private key, never a key generated by the web server).
- Independent release/installation/license/version checks at the final worker, not from browser/session/inbox hints alone.
- Independent, replay-resistant administrator consent and exact site+release digest binding, secure worker transport, root/web privilege boundary, exclusive lock, persistent audited update state.
- **Coherent and independently restorable full code + database backups with isolated SQL restore rehearsal;** MySQL DDL cannot be assumed transactionally reversible.
- Journaled, restart-safe code application and schema migrations with health/version verification and safe manual recovery on ambiguous SQL commit.
- End-to-end tests in an isolated staging clone for unauthorized/spoofed/outdated tickets, key rotation, changed archive, racing updates, failed migrations and crash injection at every step.
- Complete GitHub runner-based Quality, exact customer ZIP, web-server/browser and CodeCanyon acceptance, followed by separately approved staging cutover.

**Owner instruction:** no new backups were requested or created during this development work. This instruction does not permit skipping backup/recovery requirements during a *future live update*. The Install action must stay disabled until a safe recovery design is approved and demonstrated.

**Status:** Signed discovery/inspection/preview and guarded manual update are valid components. **Full automatic code+database installation is NOT complete.** Do not market or ship it as enabled in v1.0.0.

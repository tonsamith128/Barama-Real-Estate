System requirements

  • PHP 8.2 or newer
  • MySQL 8.0+ or MariaDB 10.6+
  • PDO and PDO MySQL
  • JSON, Mbstring, Ctype, Session, OpenSSL, Fileinfo, and cURL extensions
  • Writable Barama application runtime directories
  • Apache or Nginx. Apache uses the packaged rewrite rules; Nginx/aaPanel requires a secure front-controller rewrite (try_files $uri $uri/ /index.php?$query_string; or equivalent) for clean URLs. Existing query-compatible URLs remain supported where configured.
  • HTTPS is recommended for production use

No Node.js production runtime, Composer install command, manual migration command, or customer-created .env file is required.

Nginx setup is explained in NGINX_CLEAN_URLS.md in this documentation folder. Make sure the installer Requirements routing check passes before continuing.

One-click installation

  1. Upload and extract the customer ZIP into the intended website root.
  2. Open the main domain in a browser. Barama redirects automatically to /installer/.
  3. Complete License & Terms.
  4. Confirm Requirements.
  5. Connect an Existing Database or use Create Database with MySQL/MariaDB administrative credentials.
  6. Complete Website settings and create the first administrator.
  7. Review System Health / Finish and open the website.

The customer-facing installer always contains exactly five visible steps. Permissions checks remain inside Requirements. Requirements are shown in a clean status table, and the header language control shows flag + language options for English, Khmer, and Chinese.

Existing Database uses database credentials already created by your hosting provider. Create Database asks for database-server administrative access, creates a dedicated database and application user, verifies the new connection, and does not store the administrative credentials.

License verification

The installer uses one purchase-code/license field. Enter the purchase code or authorized license key and click Validate; no verification-method selector is shown.

The original purchase code/license key is not stored in persistent runtime state after successful activation. Review and accept the Envato license terms, author disclaimer, and support terms before continuing to Requirements.

Accounts and workspaces

  • User Account: /account
  • Company / Vendor Workspace: /developer
  • Public Company Directory: /company
  • Administrator Dashboard: /dashboard

Access is permission controlled. Public registration does not grant company/vendor or administrator permissions automatically.

Email delivery

Email delivery is intentionally kept out of the installer. Barama starts with PHP mail using the administrator email and website name.

If SMTP is required, configure it later from the application settings after installation.

Scheduled notification jobs

For saved-search alerts and queued email delivery, schedule the following command with your hosting control panel or cron facility:

php /absolute/path/to/barama/tools/notifications.php run

Useful variants:

  • php tools/notifications.php alerts all --limit=100
  • php tools/notifications.php alerts daily --limit=100
  • php tools/notifications.php alerts weekly --limit=100
  • php tools/notifications.php outbox 100

Run the command from the installed Barama package and use the PHP CLI version supported by the web application.

Signed Live Demo importer

Barama separates the clean customer installation from optional publisher-managed demo data. The installer does not prepopulate companies, projects, properties, listings, images, or policy text.

Where supported by the installed release, an activated administrator can open /dashboard/system/demo-importer?mode=auto to review the official demo preview, check their licensed access, and download a publisher-signed package.

  1. Complete the five-step installer, activate the applicable license, and make a current database/files backup.
  2. Open the Demo Importer, review the publisher identity and available official package, and use Download & Verify official ZIP where enabled.
  3. Review the package details and verify the signature before considering installation. Downloading and verifying do not themselves install demo content.
  4. Only use the guarded install action when the application explicitly enables it for your installation and confirms backup and empty-site readiness. Never bypass a disabled button or rerun the import over customer content.
  5. After a successful installation, check properties, projects, companies, media galleries, design settings, and any included public Policy Center content.

Release availability: The current pre-1.0 development line includes staged signed-package verification; automatic installation is controlled by a server-side release gate and may remain disabled on customer/production sites pending final acceptance. A package that lacks a Policy Center snapshot cannot populate Policy Center automatically. Contact support if installation is not available.

Demo packages and application updater releases are separate: demo-data versions do not upgrade the Barama PHP application.

Upgrade

  1. Create a current backup of both files and database.
  2. Upload and extract the newer supported package over the existing installation.
  3. Open the main domain. Barama redirects to /updater/ when the installed version differs from the package version.
  4. Authenticate with an active administrator account and confirm the backup.
  5. The updater validates the installed license and applies only pending ordered migrations.
  6. Return to the website and verify important customer/admin workflows before removing the backup.

Downgrades are not supported.

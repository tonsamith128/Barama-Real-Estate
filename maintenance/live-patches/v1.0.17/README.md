# Barama v1.0.17 — Email Verification and Admin Users

**Scope:** `/verify-email` and `/dashboard/users`, plus dedicated admin-only user management and audited support-session routes.

**Status:** source-matched aaPanel installation candidate. Not deployed. Production baseline expected: v1.0.16.

## Real functionality

- Rebuild the email-verification view as one vertical page; preserve existing verification, resend, logout, expiry/error states and CSRF.
- Admin Users table columns: **No | UID | User | Email | Access | State | Activity | Action**. 10 items per page, numbered navigation, Previous/Next and Go To.
- Remove irrelevant static "Administrator continuity", "Company ownership" and "Session invalidation" cards from the Users page.
- Replace the decorative header badge with a real **Add New** action, creating Normal User accounts using Barama's current password policy, user/role repositories, and email-verification queue.
- Add a dedicated authenticated **User Details** page and actual actions for **Verify**, guarded **Delete**, and **Sign in As** (10-minute audited read-only support session with explicit Exit).
- Preserve existing Suspend, Deactivate, Restore and Revoke Sessions actions, and normalize row action menu text size.
- Display stable unique eight-digit UIDs generated by deterministic full-cycle permutation of the internal numeric IDs. These are **display identifiers**, not authentication secrets, and require no migration.

## Security acceptance

Deployment does not modify the database, but post-deployment create/verify/delete operations do. Backup database separately. Check email verification, Add New, user-details view, protections on Delete and manual Verify, normal-user access denial to Admin routes, and support-session start/exit/timeout using disposable accounts. Delete refuses active, admin and linked-record accounts. Sign in As is not unrestricted impersonation; legitimate support request and mandatory read-only mode.
